# RMS 게이트 기능 설계안 (v2)

작성일: 2026-11-19 · 상태: **설계만 작성, 코드 미변경**

## 0. 목적

실생활 프로그램에서는 마이크 소리가 끊김 없이 계속 들어온다. 이 연속 입력 중 **필요 없는 구간에서는 Cnn14 계산을 생략해 연산량을 줄이는 것**이 목적이다. 단, 목표음(경적·사이렌·노크·아기 울음·유리 깨짐)을 놓치거나 알림이 늦어지지 않아야 한다.

v1은 ESC-50 5초 클립 평가에 맞춘 설계였다. 이 목적에 비추어 다시 검토했고, 그 결과를 아래에 반영했다.

## 1. v1 설계 재검토 결과

| v1 내용 | 실생활 연속 입력에서의 판단 |
|---|---|
| 절대 dBFS 기준 하나("5초 구간의 최대 프레임 레벨 < X dB"이면 생략) | **부족.** 실생활에는 디지털 무음이 거의 없다. 냉장고·에어컨·차량 소음처럼 계속되는 배경음은 항상 기준을 넘으므로 **거의 아무것도 생략되지 않는다.** 정작 줄이고 싶은 "계속되는 소리"를 걸러내지 못한다 |
| ESC-50 검증에서 기준값 선택(A·B·C안) | **운영 기준으로 쓸 수 없다.** dBFS 값은 마이크 감도·게인·AGC에 따라 달라진다. ESC-50 디지털 레벨로 정한 값(목표음 RMS 하한 0.03 ≈ -30.5 dBFS 근방에서 결정됨)은 실제 마이크로 옮겨지지 않는다 |
| ESC-50 저장 점수로 사후 분석(`analyze_rms.py`) | **절감 효과를 대표하지 못한다.** 서로 독립인 5초 클립에는 "시간의 흐름"이 없다. 무음 12구간과 원본 크기 그대로인 방해음 때문에 제외율도 실생활과 다르다. 안전성 보조 점검으로만 남긴다 |
| 구간별 레벨 저장 → 게이트 효과를 사후 계산 | **유지.** 연속 입력에서도 모든 구간을 한 번 계산해 두면 게이트 동작을 오프라인에서 다시 재생해 볼 수 있다(5절) |
| `RmsGate` 단일 진입점, 유효 길이(`valid_samples`) | **유지.** 스트림 시작(버퍼가 덜 찬 상태)과 파일 끝에서 필요하다 |
| 매 구간 5초 전체 RMS 재계산 | **개선.** 1초씩 이동하면 4초가 겹친다. 새로 들어온 1초의 프레임만 계산하면 된다 |

결론: **"무음 생략"이 아니라 "새로운 소리가 없으면 생략"하는 게이트가 필요하다.**

## 2. 핵심 아이디어

모델 입력은 최근 5초(`window_seconds`)이고, 1초(`hop_seconds`)마다 갱신한다. 따라서 매번 새로 들어오는 정보는 **최근 1초 청크뿐**이다.

- 직전 계산 결과가 "목표음 없음"이었고,
- 새 1초 청크에 배경보다 뚜렷이 큰 소리가 없다면,

새 5초 구간은 "이미 음성(목표음 없음)으로 판정된 4초 + 배경뿐인 1초"이다. 이때 **계산을 생략하고 직전 판정을 유지**한다.

이렇게 하면 일정한 배경음이 계속되는 동안에는 모델이 쉬고, 새 소리가 들어오는 순간에만 계산한다.

## 3. 게이트 결정 규칙

1초 청크마다 아래 순서로 판정한다. 먼저 해당하는 줄이 결정한다.

| 순서 | 조건 | 결정 | 이유 |
|---|---|---|---|
| 1 | 버퍼가 5초 미만(시작 직후) | 계산하지 않음 | 학습 입력 길이와 맞추기 위해(설정으로 패딩 계산 허용 가능) |
| 2 | 직전 계산 결과가 **양성**(어떤 목표음이든 검출) | **계산** | 소리가 끝나는 시점을 확인하고 반복 알림을 처리하기 위해 |
| 3 | 마지막 계산 후 `max_skip_seconds`가 지남(**기본값 = `window_seconds` = 5초**) | **계산(강제)** | 모든 오디오가 최소 한 번은 모델에 들어가도록 보장(3.1절) |
| 4 | 새 청크의 최대 프레임 레벨 < `abs_floor_dbfs` | 생략 | 마이크 자체 잡음 수준의 정적. 기존 절대 게이트 |
| 5 | **모든 주파수 대역**에서 새 청크 레벨 < 그 대역의 배경 추정치 + `delta_db` | 생략 | 새로운 소리가 없음 |
| 6 | 그 밖의 경우(**어느 한 대역이라도** 기준을 넘음) | **계산** | 새 소리가 등장함 |

- **배경 추정치 갱신**: 3과 같은 강제 계산을 포함해 계산 결과가 음성인 청크, 그리고 4·5로 생략된 청크에서만 갱신한다. **양성 판정 중에는 갱신을 멈춘다.** 그래야 길게 이어지는 사이렌이 배경으로 학습되지 않는다.
- **추정 방식**: 내려갈 때는 빠르게, 올라갈 때는 느리게 따라간다(예: 상승 최대 0.5 dB/초). 최소 통계 방식이다. 갑작스러운 큰 소리가 곧바로 배경으로 흡수되지 않게 하기 위해서다.
- **시작 보정**: 프로그램을 시작할 때 처음 3~5초 동안 주변음을 측정해 배경 추정치를 초기화한다.
- **마이크 게인 대응**: 5번 규칙은 상대값(dB 차이)이라 마이크 게인이 달라도 의미가 유지된다. 절대값은 4번의 하한에만 쓰고, 이 값도 보정 단계에서 측정한 잡음 수준으로 정한다.
- **생략할 때의 출력**: 점수를 새로 만들지 않고 `skipped=True`와 함께 직전 판정을 유지하고, 사유(`abs_quiet`, `no_change`)를 기록한다. 화면에는 "목표음 없음"으로 표시된다.

### 지연과 놓침에 미치는 영향

- **알림 지연 없음(대부분)**: 소리가 시작되면 그 소리가 담긴 첫 청크에서 6번이 계산을 일으킨다. 게이트가 없을 때와 같은 시점이다.
- **놓침 위험이 남는 경우**:
  - 배경보다 `delta_db` 이상 커지지 않는 목표음. 예: SNR 0 dB의 사이렌(3.1절)
  - 배경 추정치를 따라갈 만큼 천천히 커지는 소리
  - 두 경우 모두 3번의 강제 계산으로 최대 `max_skip_seconds` 안에는 확인된다. 이 지연을 허용할지는 검증으로 정한다.

### 3.1 낮은 SNR(0 dB) 목표음의 위험: 실측 결과

ESC-50 fold 4·5의 목표음 80개와 디지털 무음이 없는 방해음 40개를 프로젝트의 `mix_at_snr`로 혼합해 측정했다. 측정값은 "1초 청크 레벨이 같은 구간의 배경 단독 레벨보다 얼마나 올라가는지"이며, 5개 청크 중 최댓값을 썼다. 총 1,920회 시행했다.

| 목표음 | SNR 0 상승폭 중앙값<br>(광대역) | SNR 0 상승 ≥ 6 dB 비율<br>(광대역) | SNR 0 상승폭 중앙값<br>(5대역 중 최대) | SNR 0 상승 ≥ 6 dB 비율<br>(5대역 중 최대) |
|---|---:|---:|---:|---:|
| 자동차 경적 | 6.3 dB | 52% | 15.9 dB | 94% |
| 사이렌 | **4.5 dB** | **35%** | 13.3 dB | 89% |
| 문 두드림 | 10.3 dB | 87% | 22.4 dB | 100% |
| 아기 울음 | 7.2 dB | 61% | 20.3 dB | 100% |
| 유리 깨짐 | 10.5 dB | 74% | 26.1 dB | 99% |

SNR 5 dB부터는 광대역에서도 대부분 6 dB 이상 올라가고(사이렌 71%, 나머지 90% 이상), 10 dB에서는 97~100%였다.

**해석**

- **위험은 실제로 있다.** 광대역 RMS 하나로 판단하면 SNR 0에서 사이렌의 65%, 경적의 48%가 "새 소리 없음"으로 생략될 수 있다.
- **소리 유형에 따라 다르다.** 문 두드림과 유리 깨짐처럼 짧은 소리는 덜 위험하다. 이 프로젝트의 SNR은 5초 전체 RMS 기준이라 짧은 소리는 울리는 순간의 국소 SNR이 훨씬 높기 때문이다. 반대로 사이렌·경적·아기 울음처럼 계속 울리는 소리는 국소 SNR이 0 dB에 가깝다. 같은 세기의 잡음과 더하면 약 +3 dB만 올라간다.
- **대역별 비교가 효과적이다.** 사이렌과 경적은 에너지가 특정 주파수 대역에 몰려 있어서, 그 대역에서는 배경 대비 상승폭이 크다. 5개 대역으로만 나눠도 6 dB 이상 비율이 35%에서 89%(사이렌), 52%에서 94%(경적)로 올라간다.
- **배경 자체의 변동이 크다.** 방해음 단독일 때 청크 최대 레벨은 자기 하위 10% 프레임 레벨보다 중앙값 19.6 dB, 상위 10%는 38.8 dB 높았다. 그래서 배경 추정치를 "조용한 순간의 레벨(하위 백분위)"로 잡으면 `delta_db`를 아무리 정해도 변동이 큰 배경에서는 계속 계산이 일어난다. 이것은 안전하지만 절감은 없다. 배경 추정치는 **최근 청크 최대 레벨의 분포(예: 중앙값)**로 잡아야 한다.
- **한계**: 비교 기준이 "같은 구간의 정확한 배경"이라서 실제 게이트보다 유리한 조건이다. 실제 게이트는 과거로 추정한 배경과 비교한다. ESC-50 방해음에는 개 짖음 같은 사건성 소리도 섞여 있다. 최종 판단은 긴 스트림 검증(6절)으로 한다.

**설계 보완**

1. **대역별 RMS**: 1초 청크에 STFT를 적용해 5~8개 대역의 레벨을 구한다. 대역마다 배경을 추정하고, **어느 한 대역이라도** `delta_db`를 넘으면 계산한다(3절 5·6번).
2. **커버리지 보장**: `max_skip_seconds`의 기본값을 `window_seconds`(5초)로 둔다. 그러면 연속으로 생략돼도 5초마다 한 번은 계산하므로, **모든 오디오가 적어도 한 번은 모델 입력 구간에 포함된다.**
   - 최악의 경우는 "5초씩 겹치지 않게 계산하는 방식"과 같다. 대역 비교로도 못 잡은 SNR 0의 지속음은 최대 약 5초 늦게 검출된다.
   - 대가로 연산 절감률의 상한은 80%(5구간 중 4구간 생략)가 된다.
3. **배경 추정치**: 대역별로 최근 N초(예: 10초) 청크 최대 레벨의 중앙값을 쓴다. 양성 판정 중에는 갱신을 멈춘다.
4. **비대칭 원칙**: 불필요하게 계산하는 것은 절감이 줄어들 뿐이지만, 생략으로 놓치는 것은 위험하다. 애매하면 계산하는 쪽으로 기준을 정한다(`delta_db`는 작게, 대역은 OR 조건).

## 4. 연산 비용 (현재 PC에서 실측)

| 항목 | 5초 구간당 시간 | 비고 |
|---|---:|---|
| `max_frame_dbfs` (현재 Python 반복문, 200프레임) | 약 2.8 ms | 새 1초만 계산하면 약 1/5로 줄어듦 |
| `load_audio` 파일 재읽기 + 리샘플링 | 약 13.5 ms | `infer.py`는 구간마다 파일을 다시 읽음 |
| Cnn14 추론 | **미측정** | 이 PC의 `.venv`는 CPU 빌드라 CUDA 수치는 별도로 측정해야 함 |

- 게이트 자체의 비용은 무시할 만하다.
- 현재 `infer.py`는 구간마다 파일을 다시 읽어 리샘플링한다. 그래서 게이트로 모델 시간을 아껴도 전체 시간은 덜 줄어 보인다. 스트리밍 구조(링 버퍼에 한 번만 넣기)로 바꾸면 이 비용도 함께 사라진다.

## 5. 모듈 설계

### 5.1 `rms_gate.py` (새 파일, torch 불필요)

```python
class FrameLevelMeter:          # 새 청크의 50 ms/25 ms 프레임 레벨(dBFS) 계산. 청크 경계를 넘는 프레임용 꼬리 샘플 보관
class BandLevelMeter:           # 새 청크의 STFT 대역별 최대 레벨(dB), 대역은 설정값
class NoiseFloorTracker:        # 대역별 최근 N초 청크 최대 레벨의 중앙값. freeze 지원, 시작 보정
@dataclass
class GateConfig:               # abs_floor_dbfs, delta_db, bands, floor_seconds, max_skip_seconds(기본=window_seconds), calibration_seconds
@dataclass
class GateDecision:             # run_model: bool, reason: str, chunk_max_dbfs, floor_dbfs
class StreamGate:
    def push(self, chunk) -> GateDecision      # 1초 청크마다 호출
    def report(self, positive: bool)           # 모델을 실행했다면 결과를 알려 줌 → 2번 규칙, 배경 추정치 동결
```

입력 소스(파일, 마이크)와 무관한 순수 로직이다. 파일 시뮬레이션과 실시간 프로그램이 이 모듈을 **그대로 공유**한다.

### 5.2 `stream_infer.py` (새 파일)

- 소스: 파일을 1초 청크로 읽는 방식을 실시간 흉내로 사용한다. 이후 마이크 소스(예: `sounddevice`)로 교체한다.
- 5초 링 버퍼 → `StreamGate.push` → 필요할 때만 Cnn14 → `StreamGate.report`.
- `--gate off|abs|stream`으로 같은 입력에서 세 방식을 비교한다.
- **`--record-all`**: 모든 구간에 모델을 실행하고 점수와 청크 레벨을 저장한다. 게이트 동작은 오프라인에서 다시 재생한다(5.4). 이것이 v1의 "사후 계산" 원리를 연속 입력에 적용한 것이다.
- 기록: 구간 시작·끝, 실행/생략과 그 사유, 청크 레벨, 배경 추정치, 점수, 검출 결과. 요약에는 모델 호출 비율, 처리 시간, 실시간 배율(RTF)을 남긴다.
- 기존 `infer.py`는 그대로 둔다(본 실험 기록과의 호환).

### 5.3 `make_streams.py` (새 파일, 검증용 긴 음원 합성)

ESC-50 원본을 분할 규칙대로 사용한다. val 원본으로는 검증 스트림, test 원본으로는 평가 스트림을 만든다.

- 배경: 방해음 클립을 이어 붙인다. 정적인 것(rain, vacuum_cleaner, engine 등)과 변하는 것을 섞는다.
- 목표음을 무작위 시각에 넣는다. 정답 사건 구간(시작, 끝, 클래스)을 함께 저장한다.
- 목표음/배경의 SNR, 목표음 사이 간격(소리 없는 시간의 비율)을 조건으로 바꿀 수 있게 한다.
- 한계: ESC-50 클립에는 디지털 0 꼬리가 있다(표본 측정에서 35/200개 클립이 꼬리 20% 이상). 이어 붙이면 인공 무음 구간이 생기므로 제거 옵션을 둔다. 실제 녹음으로 확인하는 단계는 별도로 필요하다.

### 5.4 `replay_gate.py` (새 파일, 오프라인 파라미터 탐색)

`stream_infer.py --record-all`의 결과를 읽어 `GateConfig` 후보마다 게이트를 다시 재생한다. 생략된 구간은 직전 판정을 유지하는 것으로 처리한다.

모델을 다시 실행하지 않으므로 `delta_db`, `max_skip_seconds` 등을 빠르게 탐색할 수 있다.

### 5.5 `audio_utils.py`

- v1과 같은 변경: `load_audio_with_length`(유효 길이 반환)를 추가하고, `max_frame_dbfs`에 `valid_samples` 선택 인자를 추가한다. 기존 동작은 비트 단위로 유지한다.
- 프레임 레벨 계산은 `rms_gate.FrameLevelMeter`와 같은 함수를 쓰도록 공용화한다.
- `render_recipe`와 학습 경로는 변경하지 않는다.

### 5.6 `common.py`

검증 조건: `0 < rms_hop <= rms_frame <= hop_seconds`. 프레임 하나가 청크보다 길지 않아야 한다.

게이트 파라미터는 config에 넣지 않는다. 검증 결과물인 `stream_gate.json`(모델 해시, 임계값 해시, 검증 스트림 지문 포함)에 둔다. `thresholds.json`과 같은 원칙이다.

### 5.7 `evaluate.py`

우선순위를 낮춘다. 단일 패스와 레벨 저장 정도만 반영해, ESC-50 val·test에서 "절대 하한이 목표음 구간을 지우지 않는지"를 확인하는 안전성 점검으로 쓴다.

## 6. 검증 지표

검증 스트림에서 파라미터를 정하고, 평가 스트림에는 한 번만 적용한다.

| 지표 | 정의 |
|---|---|
| **연산 절감률** | 1 − (모델 호출 수 / 전체 구간 수). 실측 처리시간과 RTF를 함께 기록 |
| **추가 놓침 사건 수** | 게이트 없이는 검출됐지만 게이트 때문에 검출되지 않은 정답 사건 수(구간이 아닌 사건 단위) |
| **추가 알림 지연** | 사건 시작부터 첫 검출까지의 시간 증가분(평균, 최대) |
| 오경보 변화 | 시간당 오경보 수(생략으로 줄어든 것은 따로 표기) |
| 조건별 분석 | 배경 종류(정적·변동), SNR, 소리 없는 시간 비율별 절감률과 놓침 |
| **SNR 0 클래스별** | 사이렌·경적·아기 울음의 SNR 0 사건에서 추가 놓침과 추가 지연을 따로 보고(3.1절의 고위험 조건) |

**선택 규칙(제안)**: 검증 스트림에서 "추가 놓침 0, 추가 지연 최대 ≤ 1초"를 만족하는 조건 중 연산 절감률이 가장 큰 파라미터를 고른다.

## 8. 테스트 항목 (`tests/test_rms_gate.py`)

1. 정적인 배경만 계속되면 → 시작 보정 이후 강제 계산을 빼고는 모두 생략된다.
2. 배경 위에 갑작스러운 소리가 나면 → 그 소리가 담긴 첫 청크에서 계산한다(지연 0).
3. 양성 판정 중에는 배경 추정치가 동결되고, 매 청크 계산한다.
4. 아주 천천히 커지는 소리도 → `max_skip_seconds` 안에 강제 계산된다.
5. 청크 경계에 걸친 프레임의 레벨 → 5초 전체를 한 번에 계산한 결과와 같다.
6. 마이크 게인을 ±20 dB 바꿔도 → 상대 규칙(5번)의 결정이 같다.
7. 오프라인 재생(`replay_gate`)과 실제 게이트를 적용한 실행의 결정 순서가 같다(작은 대체 모델 사용).
8. 기존 `load_audio`·`render_recipe`의 출력이 바뀌지 않는다.
9. 정적 배경 위에 SNR 0의 협대역 톤(사이렌 모사)을 얹으면 → 광대역 기준으로는 생략되지만, 대역 기준으로는 첫 청크에서 계산한다.
10. 어떤 입력이든 연속 생략은 `max_skip_seconds`를 넘지 않는다(커버리지 보장).

## 9. 보고서 표현 주의

- "RMS 게이트는 새 소리가 없는 구간의 모델 계산을 생략한다. 검출 성능을 높이는 기능이 아니라 연산을 줄이는 기능이다."
- "절감률은 배경 종류와 소리 없는 시간의 비율에 크게 좌우되므로 조건별로 보고한다."
- "합성 스트림 결과는 실제 생활환경의 절감률을 보장하지 않는다."
