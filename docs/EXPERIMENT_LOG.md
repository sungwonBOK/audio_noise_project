# 실험 기록 (발표·보고서용)

`VALIDATION.md`, `REPORT_REQUIREMENTS.md`, `IMPROVEMENTS.md`, `docs/README_ORIGINAL.md`(2026-11-15~17 작성)를 하나로 합쳐 요약한 문서입니다. 수치는 모두 해당 `runs/` 폴더의 저장 결과에서 나왔습니다. 발표에서 수치를 말할 때는 각 절의 **해석 주의**를 함께 보세요.

## 1. 실행 환경과 사전 검사

- Windows, `.venv`의 CPython 3.11.15, PyTorch 2.7.1+cu128, CUDA 12.8, RTX 4060 Ti 8GB, batch 4. librosa 0.11.0, torchlibrosa 0.1.0. 전체 버전은 `requirements-cuda-lock.txt`.
- ESC-50 2,000개 파일 전체 디코딩과 ZIP 무결성 검사 통과(`docs/dataset_audit.json`).
- 공식 Cnn14 체크포인트: 327,428,481바이트, MD5 `541141fa2ee191a88f24a3219fff024e`. strict load 확인. 원저자 소스 커밋·해시는 `third_party/panns/SOURCE.json`.
- **AMP 수치 문제와 수정**: CUDA AMP(float16)에서 Log-Mel의 작은 값이 underflow되어 `-inf`가 생겼습니다. Spectrogram·Log-Mel·입력 BatchNorm은 float32로 두고 CNN과 head에만 AMP를 적용하도록 `model.py`를 고쳤습니다. float32 순전파가 원본 Cnn14 eval 경로와 일치함을 테스트로 확인했습니다.

## 2. 실험 설계 원칙 (보고서 요구사항)

- **학습 횟수(epoch)** 와 **학습 데이터 양**은 서로 다른 축입니다. 따로 그래프를 그리고 같은 뜻으로 쓰지 않습니다.
- 데이터 양은 "서로 다른 원본 수"와 "같은 원본으로 만든 혼합 입력 수"를 구분해서 적습니다.
- 데이터가 늘면 epoch당 optimizer 업데이트 수도 늘어나므로, epoch 수와 총 업데이트 수를 함께 기록합니다.
- 모델 선택은 검증 BCE, 소리별 검출 기준은 검증 F1로만 정합니다. 평가(test) 데이터는 마지막에 한 번만 씁니다.
- epoch별 검증 곡선은 기준 0.5 고정, 최종 평가는 검증에서 고른 소리별 기준(후보 0.05~0.95, 간격 0.05, 동률이면 높은 값)을 씁니다.
- 그래프 지표: 학습·검증 BCE, 검증 Macro-F1, 소리별 정밀도·재현율·F1, 목표음 없는 구간 오검출률(분모 명시), 학습시간·업데이트 수. 분류기 학습 → 일부 미세조정 단계 경계를 표시합니다.

## 3. 1차 예비 실험 — `runs/week1_20261115/`

기본 6종 방해음(rain, wind, engine, vacuum_cleaner, keyboard_typing, clapping), 학습 제외 방해음 2종(washing_machine, footsteps). 분류기 10 epoch + 일부 미세조정 5 epoch.

| 모델 | 선택된 가중치 | 평가 Macro-F1 | 목표음 없는 구간 오검출 | 학습시간 |
|---|---|---:|---:|---:|
| 깨끗한 학습 | 분류기 학습 4 epoch | 0.896126 | 9 / 76 | 163.25초 |
| 혼합 학습 | 일부 미세조정 3 epoch | 0.936087 | 8 / 76 | 191.59초 |

평가 356구간 = 깨끗한 목표음 40 + 혼합 240 + 방해음 64 + 무음 12.

해석 주의: 원본 하나를 여러 조건으로 혼합했으므로 독립 사건 356개가 아닙니다. 아기 울음 F1은 혼합 학습에서 오히려 낮아졌습니다. **본 실험(652구간)과 평가 구성이 달라 점수를 직접 비교하면 안 됩니다.**

## 4. 본 실험: 방해음 단계적 확대 — `runs/noise_expansion_20261115/`

- 목표음 학습 원본 120개 고정, 방해음 종류 6·18·30·43종(학습 원본 144·432·720·1,032개, epoch당 입력 636·924·1,212·1,524개). 작은 단계의 원본이 큰 단계에 포함되도록 구성했습니다.
- 4단계 × clean/mixed = 8모델. 시드 42, 각 10+5 epoch, 모두 같은 사전학습 가중치에서 시작.
- 검증 650구간, 평가 652구간을 모든 조건에서 동일하게 사용.
- 원본 ID `209698`, `234879`가 검증/평가 양쪽에 나타나서 검증 방해음 `4-209698-A-37.wav`, `4-234879-A-6.wav`를 제외했습니다(`plan.json`). 최대 조건에서 2,000개 중 1,950개 사용(학습 보류 방해음 48개 + 중복 2개 미사용, `verification.json`).

| 방해음 종류 | 학습 방해음 파일 | clean 평가 Macro-F1 | mixed 평가 Macro-F1 | mixed 목표음 없는 구간 오검출 |
|---|---:|---:|---:|---:|
| 6 | 144 | 0.812007 | 0.868839 | 32 / 372 |
| 18 | 432 | 0.832647 | 0.918594 | 14 / 372 |
| 30 | 720 | 0.845244 | 0.919255 | 12 / 372 |
| 43 | 1,032 | 0.838095 | 0.914096 | 11 / 372 |

산출물: `all_epoch_metrics.csv`(120 epoch 행), `data_size_metrics.csv`, `figures/`(그래프 29개), `sigmoid_analysis/`(그래프 7개).

**발표에서 쓸 수 있는 표현**: "이번 고정 시드·분할에서 혼합 학습은 모든 단계에서 깨끗한 학습보다 Macro-F1이 높았고, 방해음을 늘릴수록 혼합 학습의 오검출은 줄었지만 F1이 계속 오르지는 않았다."

해석 주의: 방해음 종류·원본 수·방해음 단독 비율·총 업데이트 수가 함께 바뀌므로 데이터 양 하나의 인과 효과가 아닙니다. 다중 시드나 유의성 검정은 하지 않았습니다.

### sigmoid 사후 분석

`analyze_sigmoid.py`로 8모델의 저장 예측을 분석했습니다(재학습·기준 변경 없음). 기준 변화 곡선은 검증 650구간으로만 그렸고, 평가 652구간은 기존 운영점 재현과 AP 집계에만 썼습니다. 검증 음성은 클래스당 594개(다른 목표음 224 + 목표음 없음 370)입니다. 점수는 보정된 실제 확률이 아닙니다.

## 5. 추가 분석 (2026-11-19)

### 사전학습만 한 Cnn14 vs 우리 모델 — `runs/baseline_pretrained_01/`

학습 없이 AudioSet 527클래스 출력을 5종으로 대응시켜(strict: 클래스당 1개 라벨, broad: 관련 라벨 몇 개의 최댓값) 같은 평가 652구간에 적용했습니다. 스크립트: `analysis/baseline_pretrained_cnn14.py`.

| 모델 | 평가 Macro-F1 | 오검출 / 372 | 0 dB 혼합 재현율 |
|---|---:|---:|---:|
| 사전학습 Cnn14 strict (학습 없음) | 0.770 | 3 | 0.50 |

### 긴 음원용 선생님 모델 기준값 — `runs/teacher_calibration/`

원본 AudioSet Cnn14로 긴 음원의 5초 창마다 라벨을 붙이기 위한 기준값입니다(ESC-50 fold 1~4로 결정, fold 5로 확인). 사용법은 `PLAY.md`.

| 소리 | 양성 → 1 | 양성 → 0 (놓침) |
|---|---:|---:|
| 자동차 경적 | 100% | 0% |
| 사이렌 | 88% | 12% |
| 문 두드림 | 75% | 25% |
| 아기 울음 | 88% | 0% |
| 유리 깨짐 | 75% | 12% |

음성(목표음 아님) → 1은 모든 소리에서 0.5% 이하입니다. 소리별 양성은 8개뿐이라 비율의 오차가 큽니다.

## 6. RMS 무음 검사 (평가 방법만 구현, 본 실험 미적용)

- `evaluate.py --rms-db <값>`: 50 ms 프레임을 25 ms 간격으로 검사해, **가장 큰 프레임 RMS도 기준 미만인 5초 구간만** 건너뜁니다. 건너뛴 구간은 점수 0과 `skipped` 표시로 기록합니다.
- 기준값은 검증에서 정하고 평가에서 한 번 확인합니다. `-60` dBFS는 예시이며 검증된 최적값이 아닙니다.
- 보고 항목: RMS 검사시간, 읽기·리샘플링·합성시간, 모델 시간, 전체 시간, 모델에 보낸/건너뛴 구간 수, RMS 때문에 추가로 놓친 양성 수.
- 알려진 한계: 길이를 맞추려고 붙인 뒤쪽 0 패딩도 RMS 검사에 포함됩니다. 개선안과 연속 입력용 게이트 설계는 `docs/RMS_DESIGN.md`(미구현).

## 7. 발표 시 말하면 안 되는 것 / 한계

- 실시간 마이크 검출은 미구현입니다. `infer.py`는 파일 입력용입니다. 실시간 시연은 확장 과제입니다(마이크 입력 → 버퍼 → CUDA 추론 → 화면 표시; 지연·반복 알림·오검출 확인 필요).
- 두 목표음 중첩, 방향 추정, 정확한 사건 시작·종료 시각, 안경 하드웨어 연동은 다루지 않았습니다. 출력은 5초 구간별 "목표음 존재" 점수입니다.
- 목표음 5종의 ESC-50 원본은 합계 200개뿐입니다. 혼합본을 늘려도 원본 다양성은 늘지 않습니다.
- 공개 데이터에서의 성능이 다른 방·마이크·거리에서의 성능을 보장하지 않습니다. 별도 녹음으로 시연해 한계를 보여주세요.
- "학습에서 제외한 방해음"은 이번 전이학습 기준입니다. Cnn14 사전학습(AudioSet)에서 본 적 없다는 뜻이 아닙니다.
- 무음 12구간은 같은 0 파형의 반복입니다.
- 테스트 통과는 코드 동작 확인이며 인식 성능 평가가 아닙니다.
